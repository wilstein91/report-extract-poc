# 증권사 리포트 핵심 항목 추출 PoC

투자 판단에 쓰는 재료를 만드는 앞단 작업입니다.
증권사 리포트 PDF에서 투자의견·목표주가·추정치를 표로 옮기는 일을
자동화할 값이 있는지 판단하기 위해 최소한만 만들어 확인합니다.

작성: Sung, Hyun-Joon · 시작 2026-09-22

## 1. 후보 지점 세 개

| | A. 리포트 → 숫자 표 추출 | B. 공시 스크리닝 | C. 읽은 자료 검색 |
|---|---|---|---|
| 업무 유형 | 입력과 전사 | 분류와 배분 | 검색 |
| 지금 처리 방식 | PDF 열어 눈으로 읽고 엑셀에 입력 | 공시 제목 훑고 볼 것만 클릭 | 파일명과 Ctrl+F |
| 병목 | 판단이 아니라 손 | 건당 판단은 쉽고 건수가 많음 | 자료에 붙은 설명이 없음 |
| 발생량 | (측정 필요) | 하루 수백 건 | (측정 필요) |
| 틀렸을 때 | 원본과 대조하면 드러남. 되돌릴 수 있음 | 중요 공시를 놓치면 되돌리기 어려움 | 못 찾으면 아쉬운 정도 |
| 채점 자료 | 숫자라서 정답이 객관적 | "봤어야 했다" 기록이 없음 | 정답 문서를 손으로 지정해야 함 |

### 고른 것과 뺀 것

**A를 골랐습니다.** 정답이 숫자라서 채점이 이분법으로 끝나고,
원본 PDF를 공개된 곳에서 받을 수 있어 자료를 오늘 안에 모을 수 있습니다.

**B는 판정 기록이 없어 뺐습니다.** 과거 공시에 대해 "봤어야 했다 / 무시해도 됐다"를
남겨둔 적이 없습니다. 교안 기준으로 이 업무에 지금 필요한 것은 모델이 아니라
판정을 기록으로 남기는 절차입니다.

**C는 자료량이 부족해 뺐습니다.** 정답을 만들 만큼 쌓인 문서가 없습니다.

### 처음부터 대상에서 제외한 것

투자 업무에서 먼저 떠오르는 세 가지는 교안의 "적용하지 않을 업무"에 해당해 제외했습니다.

| 제외한 것 | 이유 |
|---|---|
| 주가 예측 · 매매 신호 생성 | 틀렸을 때 되돌릴 수 없음. 손실이 그대로 발생 |
| "좋은 종목" 판별 | 판정 기준이 사람마다 다름. 좋은 종목의 정의를 문장으로 쓸 수 없음 |
| 백테스트로 전략 채점 | AI 문제가 아니라 결정론적 계산. 그리고 미래 참조 편향과 과최적화로 채점 자체가 신뢰할 수 없게 됨 |

AI가 들어갈 자리는 최종 판정이 아니라 재료를 만드는 앞단으로 한정했습니다.
매수 판단은 사람이 합니다.

## 2. 성공 기준

만들기 전에 적었습니다.

```
① 리포트 10건 × 7항목 = 70개 중 오류 3개 이하
② 모든 값에 원본 위치(페이지·줄)가 붙어, 틀린 값을 원본에서 찾을 수 있다
③ 읽지 못한 항목은 빈칸으로 두고 그럴듯한 값을 지어내지 않는다
```

**뽑을 항목 일곱 개**
종목명 / 증권사 / 작성일 / 투자의견 / 목표주가 / 현재주가 / 당해연도 영업이익 추정치

**숫자의 근거**
정답표를 손으로 채우면서 건당 소요 시간을 함께 기록합니다(`data/truth/ground_truth.csv`의 `기입소요초`).
이 값이 현행 수준이자 기준선의 속도가 됩니다. (측정 전 — 채우고 나서 이 자리에 기록)

**③번이 이 PoC의 어려운 부분입니다.**
언어 모델은 빈칸을 두라고 지시하지 않으면 형식에 맞는 그럴듯한 값을 채웁니다.
그 경우 오류 메시지도 없고 결과도 비어 있지 않아 검산 없이 넘어가게 됩니다.
그래서 ②번(원본 위치)과 ③번(빈칸 허용)을 성공 기준에 같이 넣었습니다.

## 3. 후보 구성

증권사 리포트는 스캔본이 아니라 디지털로 생성된 PDF라 텍스트 레이어가 있습니다.
따라서 이 PoC의 문제는 글자를 읽는 것(OCR)이 아니라,
추출된 텍스트에서 **어느 숫자가 어느 항목인지 고르는 것**입니다.

한 리포트 안에 목표주가 · 직전 목표주가 · 현재주가가 나란히 있고, 형식이 같습니다.

| | ① 기준선 | ② 로컬 모델 | ③ 외부 API |
|---|---|---|---|
| 실행 위치 | 로컬 | 노트북 | 외부 |
| 방식 | PyMuPDF 텍스트 + 정규식 규칙 | 텍스트 → 로컬 언어모델 | 텍스트 → API 언어모델 + 구조화 출력 |
| 만들어진 목적 | 이 일 전용 규칙 | 범용 | 범용 |
| 결과의 형태 | 위치를 정확히 앎 | (확인 필요) | (확인 필요) |
| 자료가 나가는가 | 안 나감 | 안 나감 | **나감** |
| 비용 | 없음 | 없음 | 호출당 과금 |

①이 이미 쓰는 방식에 해당하는 기준선입니다.
자료가 밖으로 나가면 안 되는 조건이 확정되면 ③은 점수와 무관하게 제외합니다.
(→ 결론은 `docs/sources.md` 라이선스 표와 함께 기록)
